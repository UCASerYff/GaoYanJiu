# 搞研究 4.14：移除项目管理与修复成果类别分布图

日期：2026-11-10
状态：用户已批准推荐方案

## 目标

1. 删除项目管理的全部可见功能，不再提供项目列表、详情、新建、编辑或项目步骤提醒。
2. 修复成果管理中“成果类别分布”在类别较多、名称较长或窗口较窄时的挤压、截断和标注贴边问题。
3. 保持全部历史项目记录、其他业务记录、附件、回收站、设置、研究城、钥匙串及私有备份不变。

## 范围与数据保护

- 版本从 4.13 / build 14 升至 4.14 / build 15，应用与 Widget 同步。
- 资料格式继续保持 schema32；`ResearchProject`、`PersistedLibrary.projects`、仓库编解码、迁移、备份、回收站和真实资料核验逻辑保留。
- 删除 `ProjectViews.swift` 及宿主对项目仪表盘、项目详情和项目编辑器的引用，不删除磁盘上的项目历史记录。
- `LibraryFilter.projects` 仅作为旧场景状态迁移的兼容值保留，不在真实侧栏目录、搜索、工具栏、菜单、计数或页面分支中提供可见入口。
- 旧状态若停留在项目管理，启动时迁移到在投管理的“全部”页签并清空旧搜索词。其他旧导航迁移行为保持不变。
- 通知刷新不再生成项目步骤提醒；投稿提醒及通知授权逻辑保持不变，不主动修改系统通知授权。
- 默认不启动 GUI、浏览器、真实门户或 GUI 冒烟，不伪造视觉或桌面 Widget 验收。

## 成果类别分布设计

采用用户确认的自适应横向条形图，不改变统计口径：

- 非空成果类别继续按现有 `ExistingWorkType` 顺序显示，专利继续拆分为非空专利子类及“未细分专利”。
- 每项成果只能计入一个类别；类别合计必须等于当前列表的成果数，包括专利子类与未指定署名等其他统计互不混淆。
- 将类别统计提取为可隔离测试的内部纯数据接口，视图与测试共用同一统计实现，避免复制算法。
- 图表高度随非空类别数量增长，设置合理最小高度和每行高度，不再把所有类别固定塞入 215 点。
- 横向条形的类别轴保留完整标签空间；绘图区右侧为数量标注预留固定空间，避免最大值贴边或被裁切。
- 两张上部分析卡在可用宽度不足时由左右排列切换为上下排列；宽度充足时保持并排。阈值只由实际容器宽度决定，不读取真实用户资料。
- 图表无障碍摘要继续使用同一份类别数据，标题、类别轴、数量轴与合计保持一致。

## 验证

先增加失败回归，再实现并确认通过：

1. 真实侧栏不包含项目管理；旧 `.projects` 场景迁移到 `(.all, .all)`，其他既有导航迁移不回归。
2. 类别统计覆盖普通成果、每种专利子类和未细分专利，验证唯一 ID、顺序、非空过滤和总数守恒。
3. 图表布局模型验证最小高度、多类别增长和宽窄容器排列阈值。
4. 完成框架编译及现有投稿导航、门户呈现、资金迁移、备份、资料库、回收站、Widget、Widget Store 和安装安全回归。
5. 构建并严格验签 4.14 / build 15，生成并核验新的 ZIP/SHA-256。
6. 升级前创建私有完整快照；安装后核验全部业务集合、项目历史、附件、设置、研究城和 Widget 统计零非预期差异，再清理旧程序、旧包和中间构建。
7. 核对 Spotlight、LaunchServices 与 PlugInKit 仅保留正式安装入口后，推送源码并创建 GitHub V4.14 Release。

## 明确不做

- 不删除项目历史或其他用户数据，不改变原数据路径、App Group、UserDefaults 域或钥匙串服务。
- 不改造其他统计图或其他独立应用。
- 不在本轮额外增加新栏目、新统计口径或与两项需求无关的重构。
